## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

我们想用随机输入自动找出解析类代码的崩溃，但纯随机命中率太低。请从零实现一个覆盖率引导的模糊测试框架。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ）。要求：1) 支持注册目标函数与初始输入语料，语料可手工提供或从字典生成；2) 支持覆盖率反馈：记录每次执行覆盖到的代码位置集合，新覆盖率才把输入加入语料库；3) 支持变异策略：位翻转、字节替换、插入、截断、拼接至少五种，并说明各策略适用场景；4) 支持崩溃捕获：目标函数抛异常或超时时记录输入并标记为崩溃，超时需可配置；5) 支持最小化崩溃输入：把触发崩溃的输入缩减到更短且仍能触发；6) 支持确定性复现：给定种子与语料，执行序列与发现的崩溃完全一致；7) 提供统计：执行次数、语料库大小、覆盖率增长曲线与崩溃数；8) 测试覆盖覆盖率反馈、五种变异、崩溃捕获、最小化、种子可复现与统计；`mvn -q verify` 一条命令跑通。
